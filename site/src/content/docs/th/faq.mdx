## มีค่าใช้จ่ายไหม {#does-it-cost-money}

ตัว ZenCopy เป็นซอฟต์แวร์โอเพนซอร์สที่ฟรี (Apache-2.0)
ไม่มีบัญชีและไม่มีการสมัครสมาชิก

ค่าบริการของบริการ AI เป็นเรื่องระหว่างคุณกับบริการนั้น
ด้วย[ระดับฟรีของ Google](/th/getting-started/) จะฟรีทั้งหมด — ตราบใดที่คุณไม่ลงทะเบียนวิธีชำระเงิน ก็ไม่มีทางถูกเรียกเก็บเงินได้
และถ้าใช้ AI ที่ทำงานทั้งหมดบนคอมพิวเตอร์ของคุณเอง (เช่น Ollama) ก็ไม่มีบริการภายนอกให้ต้องจ่ายตั้งแต่แรก

## เนื้อหาที่ฉันคัดลอกไปที่ไหน {#where-does-my-copied-content-go}

เฉพาะเมื่อคุณคัดลอกสองครั้งเท่านั้น เนื้อหาจึงถูกส่ง**ตรงไปยังบริการ AI ที่คุณตั้งค่าไว้** — และไม่ไปที่อื่นเลย
ไม่มีเซิร์ฟเวอร์ของ ZenCopy ไม่มีตัวกลาง และไม่มีการติดตามการใช้งาน (telemetry)
คีย์ API ของคุณก็ไม่มีวันออกไปนอกเครื่องเช่นกัน

## การคัดลอกตามปกติทำให้อะไรทำงานไหม {#does-an-ordinary-copy-trigger-anything}

ไม่
การกด <span data-os-modifier>Ctrl/⌘</span> + C ครั้งเดียวไม่เริ่มอะไร ไม่อ่านอะไร และไม่ส่งอะไรทั้งนั้น
สัญญาณคือการคัดลอกสองครั้งติดกันอย่างรวดเร็วเท่านั้น
และแม้ในกรณีนั้น เนื้อหาคลิปบอร์ดที่แอปอื่นทำเครื่องหมายว่าเป็นความลับ (เช่น โปรแกรมจัดการรหัสผ่าน) ก็ยังถูกละเว้น

## คำตอบของ AI เชื่อถือได้แค่ไหน {#how-much-can-i-trust-the-ais-answers}

AI สามารถผิดได้อย่างแนบเนียน
มันมีประโยชน์จริงสำหรับการจับใจความของข้อความ แต่กับตัวเลข ชื่อ และเรื่องที่มีผลตามมา — สัญญา ข้อความทางการแพทย์ — ให้ตรวจกับต้นฉบับก่อนนำไปใช้

## ต่างจากเครื่องมือ "AI บนข้อความที่เลือก" ตัวอื่นอย่างไร {#how-is-this-different-from-other-ai-on-selection-tools}

เครื่องมือส่วนใหญ่ในกลุ่มนี้มีเฉพาะบน macOS ใช้ได้กับข้อความที่เลือกเท่านั้น และผูกกับ AI ของผู้ขายรายเดียวหรือกับการสมัครสมาชิก
ZenCopy ทำงานบน **Windows, macOS และ Linux** รองรับ**ข้อความ รูปภาพ และไฟล์** และให้**คุณเป็นผู้เลือกบริการ AI** (OpenAI / Google / Anthropic / เกตเวย์องค์กร / Ollama ในเครื่อง)
และไม่ได้จบแค่ถามตอบรอบเดียว จากช่องกรอกใต้คำตอบ คุณ**สนทนาต่อได้ตรงนั้นเลย**
[พรอมต์ไหนจะทำงานก็อยู่ในมือคุณเช่นกัน](/th/configuration/#rulesjson)
ไม่มีบัญชี ไม่มีการสมัครสมาชิก ไม่มี telemetry — เป็นซอฟต์แวร์โอเพนซอร์ส

## ต่างจากเว็บไซต์แชตอย่าง ChatGPT อย่างไร {#how-is-this-different-from-chat-sites-like-chatgpt}

เว็บไซต์แชตคือที่ที่คุณต้อง "เดินไปหา" เพื่อคุย
ZenCopy **เรียกบทสนทนาขึ้นมาบนสิ่งที่คุณกำลังดูอยู่**
เลือกแล้วคัดลอกสองครั้ง — ข้อความที่กำลังอ่าน ภาพหน้าจอข้อผิดพลาด หรือ PDF ที่ได้รับ กลายเป็นจุดเริ่มต้นของบทสนทนาโดยไม่ต้องวางเลย
คำตอบแรก (สรุป แปล ฯลฯ) เริ่มโดยอัตโนมัติ ส่วนที่เหลือก็เหมือนแชตทั่วไป
โมเดลคุณเลือกเอง และประวัติไม่ถูกเก็บไว้บนเซิร์ฟเวอร์ใด (บทสนทนาอยู่แค่ตรงนั้น จนถึงการคัดลอกครั้งถัดไป)

## มีแอปอื่นตอบสนองต่อ Ctrl/⌘ + C + C ด้วย (เช่น DeepL) {#another-app-also-reacts-to-ctrl--c--c-eg-deepl}

ไม่มีแอปใดเป็นเจ้าของสัญญาณ "คัดลอกสองครั้ง" ในระดับ OS ได้
ถ้ามีแอปอื่นฟังสัญญาณเดียวกันอยู่ (ตัวที่รู้จักกันดีคือ DeepL) แอป**ทั้งสอง**จะตอบสนองและป๊อปอัปจะขึ้นมาสองอัน
ZenCopy ไม่ดักและไม่บล็อกอีเวนต์คีย์ใด ๆ จึงไม่มีอะไรเสียหาย — อาการมีเพียงเท่านั้นเอง
ให้ปิดทางลัดในแอปที่คุณใช้น้อยกว่า (สำหรับ DeepL: Settings → General → ทางลัดสำหรับการแปล)

## ป๊อปอัปไม่ปรากฏเลย (macOS) {#the-popup-never-appears-macos}

เกือบแน่นอนว่าเป็นเรื่องสิทธิ์การเข้าถึง
อนุญาต **การตรวจสอบสัญญาณเข้า** ให้ ZenCopy ใน การตั้งค่าระบบ → ความเป็นส่วนตัวและความปลอดภัย แล้วปิดและเปิดแอปใหม่
(สิทธิ์นี้คือวิธีที่แอปใช้สังเกตว่ามีการกดคัดลอกสองครั้ง)

## ไม่มีผลลัพธ์กลับมา / แจ้งว่าหมดเวลา {#no-result-comes-back--it-says-it-timed-out}

ถ้าการตอบกลับเงียบไป 90 วินาที ZenCopy จะถือว่ารอบนั้นล้มเหลวแทนที่จะรอไปเรื่อย ๆ
ตรวจสอบการเชื่อมต่ออินเทอร์เน็ตและการตั้งค่าบริการ AI (คีย์ API เป็นต้น) แล้วกด **ลองใหม่**
AI ในเครื่องอาจใช้เวลาโหลดนานในครั้งแรก เวลาหมดเวลาจึงตั้งไว้ค่อนข้างนานโดยเจตนา

## รองรับสภาพแวดล้อม Linux แบบใดบ้าง {#which-linux-environments-are-supported}

**GNOME บน Wayland และ X11**
บน GNOME Wayland โปรเซสเบื้องหลังไม่สามารถสังเกตคีย์หรือคลิปบอร์ดได้โดยการออกแบบ ZenCopy (ผ่านเครต [`copycopy`](https://crates.io/crates/copycopy)) จึงมาพร้อมส่วนขยาย GNOME Shell ขนาดเล็กที่ตรวจจับการคัดลอกสองครั้งจากภายใน compositor
ส่วนขยายนี้ถูกติดตั้งลงโปรไฟล์ผู้ใช้ของคุณโดยอัตโนมัติเมื่อเปิดครั้งแรก (ไม่ต้องใช้ sudo) และเริ่มทำงานหลังออกจากระบบแล้วเข้าใหม่หนึ่งครั้ง
บน X11 ใช้ตัวฟังคีย์แบบพาสซีฟธรรมดาได้ เช่นเดียวกับบน Windows
compositor Wayland อื่น ๆ (KDE Plasma, แบบที่ใช้ wlroots) ไม่มีวิธีสังเกตทริกเกอร์โดยไม่ใช้สิทธิพิเศษ จึงยังไม่รองรับ — แอปทำงานได้ แต่ทริกเกอร์จะไม่ตอบสนอง

## ไอคอนถาดระบบไม่แสดง (Linux) {#the-tray-icon-does-not-show-up-linux}

ไอคอนถาดระบบของ ZenCopy ใช้โปรโตคอล AppIndicator
GNOME ของ Ubuntu รองรับตั้งแต่แรก แต่ GNOME แบบดั้งเดิม (เช่น Fedora) จะไม่แสดงอะไรจนกว่าจะติดตั้งส่วนขยาย Shell ชื่อ **AppIndicator and KStatusNotifierItem Support**
ไม่ว่ากรณีไหน ตัวแอปเองยังทำงานได้ — เมนูถาดระบบเป็นเพียงทางเข้าหนึ่งเท่านั้น
