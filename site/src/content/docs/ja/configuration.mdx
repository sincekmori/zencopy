設定画面には **AI・プロンプト・一般**の 3 つのタブがあります。

## AI {#ai}

このタブで決めるのは「コピーした内容を、どの AI に頼むか」です。

![設定画面の AI タブ。プロバイダーの選択、モデル、API キーの欄](/ja/screenshots/settings-ai.png)

正解は人によって違います。
自分に当てはまる見出しから読んでください。

### まずは無料で使いたい {#free-with-gemini}

ほとんどの人はこれで十分です。
[はじめる](/ja/getting-started/#connect-an-ai)の手順どおり Google の無料キーを作り、ようこそ画面に貼り付けていれば、このタブはすでに設定済みです。

キーを作り直したときは、プロバイダーが **Google** になっていることを確かめて、**API キー**の欄に新しいキーを貼り、**保存**を押すだけです。
モデル名の欄には、速さと賢さのバランスがよいものが最初から入っています。
変えたくなるまで、そのままでかまいません。

### ChatGPT や Claude を契約している {#bring-a-paid-key}

OpenAI（ChatGPT の提供元）や Anthropic（Claude の提供元）の AI も使えます。
プロバイダーで **OpenAI** または **Anthropic** を選び、その提供元の API キーを貼るだけです。

1 つだけ、先に知っておくとお金の混乱を防げます。
**ChatGPT Plus や Claude Pro の月額契約と、API キーは別の契約です。**
月額を払っていても API キーは含まれず、API キーの料金は使った分だけの従量制で、それぞれの提供元のページで別途発行します。
とはいえ ZenCopy の使い方（数百文字をコピーして要約する、など）での従量料金はごく小さく、月に数十円から数百円に収まる人がほとんどです。
使った量は[利用統計](/ja/configuration/#general)でいつでも確かめられます。

### ゲートウェイの設定を使う {#use-a-gateway-config}

ゲートウェイ（共有された AI の入口）を運用している環境では、管理者が「この設定を使ってください」と JSON と呼ばれるテキスト（またはファイル）を配っていることがあります。
その場合はキーを自分で作る必要がありません。

中身のテキストは呪文のように見えますが、**読めなくてかまいません**。
やることは 3 つです。

1. プロバイダーの選択肢から **JSON** を選ぶ
2. 渡されたテキストを、表示された編集欄に丸ごと貼り付ける
3. **保存**を押し、続けて**テスト**を押す

「接続できました」と出れば完了です。
貼り付けた内容に不備があると、保存の時点で赤いメッセージが出ます。
そのメッセージごと、配ってくれた担当者に伝えてください。あなたの操作ミスではありません。

なお JSON の編集欄では、API キーは普段伏せ字になっています。
画面を共有していても映らないためで、**API キーを表示**を押したときだけ見えます。

### 何も端末の外に送りたくない {#run-a-local-ai}

AI を自分のパソコンの中だけで動かす方法もあります（Ollama というアプリが有名です）。
コピーした内容が一切外に出ないので、機密文書にも使えます。
そのぶん、パソコンの性能なりの速さと賢さになります。

Ollama を入れてモデルを 1 つダウンロードしたら、ZenCopy 側はプロバイダーで **OpenAI 互換**を選び、次の 2 つを書きます。

- **ベース URL**: `http://localhost:11434/v1`
- **デフォルトモデル**: Ollama でダウンロードしたモデル名（例: `gemma4:e4b`）

そのまま[コピーして使える設定例](/ja/recipes/)も用意しています。

### 接続を確かめる {#test-the-connection}

どの方法で設定した場合も、**テスト**ボタンで今すぐ確かめられます。
「接続できました」と出ればすべて正常です。
失敗したときに見直すのは 4 つだけです: モデル名、API キー、ベース URL（使っている場合）、そしてインターネット接続。

### あなたについて {#about-you}

このタブには**あなたについて**という欄もあります。
自分の役割や好みを、普段の言葉で数行書いておく場所です。

> 例: 「営業職。お客様へのメールが多い。丁寧すぎない敬語で、結論を先に。」

書いておくと、すべてのプロンプトの結果があなた向けに調整されます。
説明はあなたの知識に合った深さになり、文章はあなたの好みの調子になります。
関係のないタスクには影響せず、内容が結果にそのまま現れることもありません。

## プロンプト {#prompts}

「コピー 2 回のあとに何をするか」の一覧です。

![設定画面のプロンプトタブ。プロンプトの一覧と振り分けの設定](/ja/screenshots/settings-prompts.png)

最初から入っている 5 つ（自動、要約、解説、翻訳、清書）は、開いて中身を見られます。
自分で書くときの実例になります。

### 自分のプロンプトを作る {#create-your-own-prompt}

**新しいプロンプト**を押すと、書くのは 2 つだけです。
名前と、やってほしいこと。

![プロンプトの作成画面。名前と指示の入力欄](/ja/screenshots/prompt-editor.png)

> 例: 名前「3 行まとめ」、指示「3 行で要約してください」

指示をうまく書く自信がなくても大丈夫です。
やりたいことを雑に書いて **AI で下書き**を押すと、設定済みの AI が整った指示に仕上げてくれます。
仕上がりが気に入らなければ、もう一度押すとさらに練り直します。

### 人と共有する {#share-prompts}

作ったプロンプトは**エクスポート**でファイルとして書き出して人に渡せます。
受け取る側は**インポート**を開いて、本文を貼り付けるかファイルを選ぶだけです。

![プロンプトのインポート画面。貼り付け欄とファイル選択](/ja/screenshots/prompt-import.png)

### 振り分け {#routing-rules}

初期状態では、どのコピーも「自動」が内容を見て最適な処理を選びます。
コピーの種類（テキスト、画像、ファイル）ごとに、実行するプロンプトを変えられます。

さらに**新しいルール**で、条件つきの振り分けも作れます。

![新しいルールの作成画面。アプリ名や URL などの条件と、動かすプロンプトの選択](/ja/screenshots/new-rule.png)

> 例: 「Slack で 200 文字以上をコピーしたときは、要約を動かす」
> 例: 「PDF ファイルをコピーしたときは、自作の『契約チェック』を動かす」

条件は上から順に試され、最初に当てはまったルールが勝ちます。

### プロンプト作りごと AI に任せる {#let-an-ai-write-the-prompt}

プロンプトの作成自体を、普段使っている AI チャットに任せることもできます。
以下を貼り付けて、空欄を埋めてください:

```text
https://zencopy.app/llms-full.txt を読んでください。これは、プロンプトのファイル形式、テンプレート変数、振り分けの仕組みを含むZenCopyの完全なドキュメントです。その後、次の処理を行うZenCopyプロンプトを作成してください：[やりたいこと]。ZenCopyの「設定 → プロンプト → インポート」にそのまま貼り付けられるように、フロントマター付きの完全なプロンプトファイル（Markdown）を1つのコードブロックで出力してください。そのプロンプトが特定のアプリや特定のサイトでのみ機能する場合は、どの振り分けルールを設定すべきかを説明する文章を1文追加してください。
```

返信内のコードブロックは、そのまま**設定 → プロンプト → インポート**に貼り付けられます。
ドキュメントでは解決できない疑問（「ZenCopyでこんなことできる？」など）がある場合は、<RepomixLink>ワンクリックで関連ソースをパック</RepomixLink>して、その結果を同じAIに渡してください。

## 一般 {#general}

アプリ全体の見た目とふるまいです。

![設定画面の一般タブ](/ja/screenshots/settings-general.png)

- **ポップアップの位置**：結果を画面のどの隅に出すか。
- **ログイン時に起動**：パソコンを付けたら ZenCopy も待機。
- **開発者モード**：プロンプト開発時のためにテンプレート変数を表示します。プロンプトを作り込むまでは無関係です。
- **利用統計**：モデルを動かすたびに、この端末の中の記録へ 1 行追加します。かかったお金の概算と、月の上限（超えそうなら実行前に止める）はこの記録から計算されます。
  記録はあなただけのもので、どこにも送信されません。オフにもできますが、オフにするとコスト表示と上限も使えなくなるため、切る前に確認の画面が出ます。
- **送信前の確認**：画像やファイルを AI に送る前に、ひと言たずねるかどうか。
- **文字サイズ**：小 / 標準 / 大。ポップアップと設定画面の全体が変わります。
- **テーマ**：ライト / ダーク / システムに合わせる。
- **表示言語**：標準では OS に合わせます。
- **初期化**：すべての設定と API キーを消して、最初の状態に戻します。実行前に確認の画面が出ます。

## 設定ファイル（上級者向け） {#config-files-for-power-users}

ここから先は、テキストファイルを直接編集する話です。
**画面の設定だけで主要な機能はすべて使えるので、興味がなければ読み飛ばしてかまいません。**

ファイルはユーザーごとのアプリ設定ディレクトリから読み込まれます。
正確なパスは起動時のログにも出力されます:

<Tabs syncKey="os">
  <TabItem label="Windows">`%APPDATA%\app.zencopy`</TabItem>
  <TabItem label="macOS">`~/Library/Application Support/app.zencopy`</TabItem>
  <TabItem label="Linux">`~/.config/app.zencopy`</TabItem>
</Tabs>

振り分けの既定値はアプリに埋め込まれており、`rules.json` は常にその**上書き**としてだけ働きます。
プロンプトのファイルは**追加専用**です:
新しいプロンプトを定義するもので、組み込みのプロンプトは不可侵です（同じ id を名乗るローカルファイルは無視されます）。
編集は次のトリガーから反映され、再起動は不要です。

### `ai-sdk-catalog.json` {#ai-sdk-catalogjson}

プロバイダーと **role → モデル** の対応。
設定画面の AI タブ（JSON を含む）が読み書きしているのは、まさにこのファイルです。
ファイル形式の本家は [ai-sdk-catalog](https://github.com/sincekmori/ai-sdk-utils/tree/main/packages/catalog#readme) です。
全フィールドの説明（エディタで検証・補完が効く `$schema` を含む）はそちらにあり、[`examples/`](https://github.com/sincekmori/ai-sdk-utils/tree/main/packages/catalog/examples) には 3 サイズの設定例が揃っています。
ZenCopy 向けの出発点（設定 UI が書く形、ローカル Ollama、プロンプト用の role）は[レシピ集](/ja/recipes/)を見てください。

1 点だけ、ファイル形式ではなく ZenCopy 側の要件があります: `roles` には必ず **`default`** を含めてください。
frontmatter で別の role を指定しないプロンプトはすべて `default` で実行され、設定画面の接続テストも `default` に ping します。

API キーはこのローカルファイルに直接書きます（設定 UI が書くのもこの形式）。キーが端末の外に出ることはありません。
環境変数は読み込みません。GUI アプリはシェルではなく OS から起動されるため、`.zshrc` などで export した変数はそもそも届かないからです。
このファイルは読み込みのたびにスキーマ検証されます。
壊れた編集は、ポップアップと設定エディタに明確なメッセージとして表示され、黙って失敗することはありません。

### `rules.json` {#rulesjson}

どの種類のキャプチャをどのプロンプトが処理するか:
フラットな `kind → prompt` の対応と、より優先される任意の `overrides` リスト（先勝ち）。
kind は `text`、`image`、`files` の 3 種類で（書式付きのコピーは `text` として扱われます）、初期状態ではどの種類も「自動」に振り分けられます。
フラットな対応と `overrides` はアプリ内（設定 → プロンプト → 振り分け）から編集できるので、このファイルを直接編集する必要はほとんどありません。

```json
{
  "text": "zencopy-auto",
  "image": "zencopy-explain",
  "files": "zencopy-auto",
  "overrides": [{ "when": { "app_name": "Slack", "min_chars": 200 }, "prompt": "summarize" }]
}
```

`when` の条件: `kind`（3 種類のいずれかに完全一致）、`app_name`、`exec_name`、`window_title`、`url`（いずれも `*` ワイルドカード対応）、`file_name`（コピーしたすべてのファイル名がマッチするワイルドカード。大文字小文字は区別しません。例: `*.pdf`）、および `min_chars` / `max_chars`。

`image` と `files` のキャプチャでは、内容そのものがモデルに送信されます（1 回あたり合計 10 MB まで）。
ファイルの種類は名前ではなく**中身**から判定されます:
画像・PDF・音声はそのまま添付され、テキストファイル（Markdown、ソースコード、CSV など）はキャプチャのテキストそのもの（`{{ text }}`）になり、内容をコピーした場合とまったく同じように扱われます。
Office ドキュメント（Word、Excel、PowerPoint）もテキストになります。内容は抽出されて送信されますが、レイアウトや画像は送信されません。
文字コードは自動判定され、Shift_JIS や UTF-16 のようなレガシーな形式も変換されます。
どちらでもないものは明確なメッセージつきでお断りします。
モデルがファイルを区別し場所を把握できるように、内容と一緒にフルパスも送信されます。
バイナリの添付はテキストより料金がかかりうるため、送信前にポップアップが確認します（テキストファイルは確認なしで実行されます）。
確認はその場または設定でオフにできます。

### `prompts/*.md` {#promptsmd}

1 ファイル = 1 プロンプト: YAML フロントマター + [Liquid](https://liquidjs.com) のプロンプト本文。
この 1 ファイルがそのまま共有形式でもあります（設定 → プロンプト → インポートで、本文の貼り付けかファイル選択で受け取れます）。

```markdown
---
id: summarize
label: 要約
role: default
instructions: あなたは簡潔なアシスタントです。
---

次の内容を {{ locale }} で3行に要約してください:

{{ text }}
```

| フロントマター | 意味                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| `id`           | `rules.json` から参照される名前（省略時はファイル名。接頭辞 `zencopy-` はプリインストールプロンプト専用） |
| `label`        | ポップアップに表示                                                                                        |
| `role`         | 実行に使う catalog の role（省略時は `default`）                                                          |
| `instructions` | システムプロンプト（Liquid テンプレート）                                                                 |

テンプレート変数と、ブラウザで段落をコピーした場合の値の例:

| 変数                 | 例                                                      |
| -------------------- | ------------------------------------------------------- |
| `{{ text }}`         | コピーした本文（HTML のリッチコピーは Markdown に変換） |
| `{{ markup }}`       | リッチコピー時の HTML/RTF ソース                        |
| `{{ format }}`       | `html`（または `rtf`。プレーンコピーでは空）            |
| `{{ file_name }}`    | `report.pdf`（コピーした最初のファイル名）              |
| `{{ file_names }}`   | コピーしたすべてのファイル名（1 行に 1 つ）             |
| `{{ file_paths }}`   | コピーしたすべてのファイルのフルパス（1 行に 1 つ）     |
| `{{ app_name }}`     | `Safari`                                                |
| `{{ exec_name }}`    | `Safari` / `chrome.exe`                                 |
| `{{ exec_path }}`    | `/Applications/Safari.app/Contents/MacOS/Safari`        |
| `{{ window_title }}` | `料金プラン – Example`                                  |
| `{{ url }}`          | `https://example.com/pricing`（ブラウザのときのみ）     |
| `{{ process_id }}`   | `8123`                                                  |
| `{{ now }}`          | `2026-07-08 20:15:00`                                   |
| `{{ locale }}`       | `ja`                                                    |

さらに ZenCopy 独自の `language_name` フィルタがあります。
`{{ locale | language_name }}` は「ja」ではなく「Japanese」と展開され、プロンプトとして自然に読めます。
実際にどんな値が入るかは、設定で**開発者モード**をオンにすると確認できます。
キャプチャごとのテンプレート変数が、ポップアップに JSON で表示されます。

シンプルなプロンプト（名前と指示だけ）は設定ウィンドウからも作成できます。書き出されるのはまさにこの形式のファイルです。

#### 高度なテンプレート {#advanced-templating}

`instructions` フロントマターと本文は、どちらも完全な [LiquidJS](https://liquidjs.com/tags/overview.html) テンプレートです:
条件分岐・ループ・[フィルター](https://liquidjs.com/filters/overview.html)がすべて使えます。
1つのプロンプトを、コピー元に応じて振る舞い分けることもできます:

```markdown
---
id: context-aware
label: 文脈で切り替え
---

{% if url contains "github.com" %}
このコードをレビューして、最大のリスクを1つ指摘してください:
{% elsif app_name == "Slack" %}
このチャットのスレッドを2行で要約してください:
{% else %}
これを {{ locale }} で説明してください:
{% endif %}

{{ text | truncate: 8000 }}
```

## ログ {#logs}

構造化ログ（秘密情報とコピー内容は redact 済み）は、dev ではターミナル、release ではローテーション付きファイルに出力されます:

<Tabs syncKey="os">
  <TabItem label="Windows">`%LOCALAPPDATA%\app.zencopy\logs`</TabItem>
  <TabItem label="macOS">`~/Library/Logs/app.zencopy/`</TabItem>
  <TabItem label="Linux">`~/.local/share/app.zencopy/logs`</TabItem>
</Tabs>
